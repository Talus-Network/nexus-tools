# Agent API Tools

This crate serves the shared signed HTTP `query` and `retrieve-key` Tools and runs the provider lifecycle service for the four coin-specific Tools generated by [`authority-pattern/onchain/agent_api`](https://github.com/Talus-Network/nexus-tools/tree/main/authority-pattern/onchain/agent_api). See the [bundle guide](https://github.com/Talus-Network/nexus-tools/blob/main/authority-pattern/README.md) for package-local commands, Move test support, and deployment preparation. The local mock provider and demo use synthetic state; they do not publish Tools or submit chain transactions.

See the [Nexus Tool guide](https://docs.talus.network/talus-documentation/developer-docs/index/tool), [Nexus SDK Toolkit guide](https://github.com/Talus-Network/nexus-sdk/tree/main/toolkit-rust), and [Sui developer setup](https://docs.sui.io/guides/developer/getting-started) for Toolkit, Nexus, and Sui environment setup.

## On-chain registration identity

On-chain registration allocates its binding ID from the Sui transaction context and returns it as the named `binding_id` output. Callers cannot choose an ID, so separate cashiers cannot collide in the provider's global binding and key namespace. Retain the public, non-secret ID returned by registration for later `charge`, `authorize`, and `revoke` calls.

## Signed HTTP schemas

Both Tools require signed HTTP v3 authorization bound to the exact schema-ordered canonical SDK input commitment. Requests use the Toolkit resolved-port form: each JSON port value is encoded as `NexusData::inline_data` and supplied under `ports`.

| Tool | JSON input | Successful JSON output before canonical BCS encoding |
| --- | --- | --- |
| `xyz.taluslabs.agent_api.query@<TOOL_FQN_VERSION>` | `{ "binding_id": "0x...", "payload": { "prompt": "..." } }` | `{ "ok": { "result": JSON, "cumulative_usage": u64 } }` or `{ "err": { "reason": string } }` |
| `xyz.taluslabs.agent_api.retrieve-key@<TOOL_FQN_VERSION>` | `{ "binding_id": "0x..." }` | `{ "ok": { "envelope": { "version": u8, "suite": string, "ephemeral_public_key": string, "nonce": string, "ciphertext": string } }` or `{ "err": { "reason": string } }` |

Successful Tool responses use the canonical `application/vnd.nexus.canonical-tool-response+bcs` body and the pinned SDK `OffchainToolOutput` schema order. Provider keys, owner private keys, and caller-supplied replacement public keys are absent from both input schemas. `retrieve-key` returns an authenticated X25519/HKDF-SHA256/XChaCha20-Poly1305 envelope only for the public key committed at registration; export-disabled bindings return a Tool error.

## Generate a payment-coin package

Create a JSON generator config with `package_name`, `coin_slug`, a concrete fully qualified `coin_type`, a `dependencies` array of `{ "alias": "...", "mvr": "@publisher/package" }`, and `named_addresses` for any non-numeric address aliases in the coin type. The type can be a third-party coin or a nested generic type; the generator validates addresses and never edits an existing destination.

```json
{
  "package_name": "agent_api_usdc",
  "coin_slug": "usdc",
  "coin_type": "usdc::coin::USDC",
  "dependencies": [{"alias": "usdc", "mvr": "@publisher/usdc"}],
  "named_addresses": {"usdc": "0x1234"}
}
```

Run this from the `authority-pattern/` directory, replacing the example type and MVR package with the coin's published values:

```sh
python3 onchain/agent_api/generate.py --config ./agent-api-usdc.json --output ./agent-api-usdc
sui move build --path ./agent-api-usdc
sui move test --path ./agent-api-usdc
```

The generated package has concrete `register`, `charge`, `authorize`, and `revoke` execute ABIs for the selected coin. The templates, SUI and test-coin fixtures, and generator tests are in [`authority-pattern/onchain/agent_api`](https://github.com/Talus-Network/nexus-tools/tree/main/authority-pattern/onchain/agent_api).

## Provider adapter contract

An external provider used by `Provider` must pass `verify_capabilities` for key creation, idempotent credit, key disable, cumulative final-usage reads, and request idempotency. `credit` uses the immutable charge-event ID as its idempotency key. `query` uses the one-use Nexus nonce; an exact retry returns the original result and a changed payload under that key is rejected. Provider management calls require separate backend/operator credentials; the owner API key permits provider queries only.

`disable` must prevent new owner-direct and Nexus queries and be safe to repeat. `final_usage` must return the final monotonic cumulative usage after disable so the worker can settle the consumed amount and refund the remaining reserve to the original wallet. A provider without these lifecycle and idempotency guarantees is rejected during capability validation. The bundled mock provider persists keys, credits, usage, and idempotency outcomes in SQLite and exposes operator-only lifecycle routes. Disable atomically sets its cumulative usage ceiling to already-consumed usage, preserving historical usage and idempotency records while leaving zero spendable credit.

## Configuration and worker

The Toolkit process requires `signed_http.mode` set to `required` in `NEXUS_TOOLKIT_CONFIG_PATH`, plus `AGENT_API_DB_PATH`, `AGENT_API_MASTER_KEY` (64 hexadecimal characters), `AGENT_API_PROVIDER_URL`, and `AGENT_API_PROVIDER_OPERATOR_KEY`. Configure event ingestion with `AGENT_API_DEPLOYMENTS`, a JSON array with one entry per generated coin package. Each entry binds its event `rpc_url`, `package_id`, `module`, `coin_type`, `cashier_id`, and matching `settlement_cap_id`; one coin uses a one-element array. The backend rejects malformed addresses/types, duplicate cashiers or capabilities, and overlapping package/module event queries because their cursors and event filters would be ambiguous. The former single-deployment environment tuple is no longer read.

```json
[
  {
    "rpc_url": "https://fullnode.testnet.sui.io:443",
    "package_id": "0x...",
    "module": "accounting",
    "coin_type": "0x2::sui::SUI",
    "cashier_id": "0x...",
    "settlement_cap_id": "0x..."
  },
  {
    "rpc_url": "https://fullnode.testnet.sui.io:443",
    "package_id": "0x...",
    "module": "accounting",
    "coin_type": "0x123::test_coin::TEST_COIN",
    "cashier_id": "0x...",
    "settlement_cap_id": "0x..."
  }
]
```

Run the worker from `authority-pattern/` with `cargo +stable run --locked --manifest-path offchain/Cargo.toml --bin agent-api -- worker`. It additionally needs `AGENT_API_SUI_GRPC_URL`, `AGENT_API_SETTLEMENT_SIGNER_KEY_B64` for the address owning each configured settlement capability, and optionally `AGENT_API_SETTLEMENT_GAS_BUDGET` (defaults to `50000000`). The worker checks each capability's ownership, polls each configured package/module with Sui's `MoveEventModule` query filter, keeps an independent durable cursor for each configured package/module/coin/cashier stream, routes pending settlements by cashier, builds coin-specific settlement/refund transactions, waits for checkpoint confirmation, and resumes pending phases after restart. Keep provider operator credentials and owner private keys outside Tool inputs and logs.

Keep each deployment configured while any binding from that origin is active or has an unconfirmed refund. Startup rejects a missing or changed origin until all bindings are fully refunded, after which it can be removed. Active usage settlements update cumulative usage and earned revenue without entering the refund queue; refund submission begins only after revocation fixes the final usage and exact remaining reserve. A conflicting authorization event with an already-used global nonce is durably rejected without replacing the original grant, so event ingestion can continue. Completed requests remain replayable from the durable response cache after full retirement without provider access; the first successful completion fixes the response even when concurrent key-retrieval retries produce different randomized envelopes.

## Owner-side key decryption

Decrypt the returned envelope in the owner's trusted environment with the private key matching the registration-approved public key. The decrypted provider key is returned as bytes and should be used only for an owner-authorized provider request; never log or send it back to Nexus.

```rust
use agent_api::crypto::{decrypt_export, KeyEnvelope};

fn decrypt_for_owner(owner_private_key: &[u8; 32], envelope: &KeyEnvelope) -> anyhow::Result<String> {
    let provider_key = decrypt_export(owner_private_key, envelope)?;
    Ok(String::from_utf8(provider_key)?)
}
```

## Local demo

The demo exercises registration without payment, simulated wallet funding and charge, one signed-style Nexus query, owner-direct provider queries, usage settlement, and refundable reserve accounting with the bundled mock provider. Its chain events and transactions are simulated and it does not connect to a shared network. From `offchain/`, run:

```sh
cargo run --locked -p agent-api -- demo
```
